### steve.park(박상욱)
# 2026-08-10 Daily Report

## 1. 약관 코퍼스 정형화와 내장

카카오 약관 원문을 문서명·시행일·조항 번호·제목·본문 구조로 정리하고, 조항 단위로 청킹한 72개 문서를 압축하여 노트북 안에 포함했다. 외부 파일 없이 제출 파일 하나만으로 실행되는 구조를 구현하면서, RAG에서는 생성 모델보다 먼저 정확하고 일관된 원문 코퍼스를 준비하는 일이 중요하다는 점을 배웠다.

## 2. BM25 검색기와 검색 일반화 개선

BM25 검색기에 동적 Top-K, 문서명·조항 번호 기반 재정렬, 후보군 확대와 문자 2-gram 검색을 적용했다. 공개 문항 MRR 1.00을 유지하면서 자체 합성 30문항의 MRR을 0.6167에서 0.7667로 개선했으며, 공개 문제에만 맞춘 검색보다 표현이 달라지는 비공개 질문을 견딜 수 있는 일반화 검증이 필요하다는 점을 확인했다.

## 3. Qwen 기반 RAG 답변 생성기 구현

Qwen2.5-7B-Instruct를 NF4 4-bit로 로딩하고 검색된 근거만 사용해 답변을 생성하도록 연결했다. 질문이 요구한 목록 개수와 복합 요소를 추출하고, 답변이 문장 중간에서 잘리거나 목록이 미완성인 경우에만 후속 생성을 수행하도록 구현했다. 모델 크기와 양자화뿐 아니라 프롬프트의 생성 순서와 출력 범위가 답변 정확도에 큰 영향을 준다는 점을 배웠다.

## 4. 반복 실험과 평가 기준 중심의 버전 관리

각 실험 결과를 MRR, 핵심 사실 포함 여부, 정확성·근거성·완결성·명료성, 응답 시간으로 비교하고 변경 내용·선택 이유·비교 대상·실패 원인을 `version.md`에 기록했다. 속도는 예선 점수에 직접 포함되지 않으므로 정상 실행을 보장하는 범위에서 정확성과 근거성을 우선해야 하며, 결과를 본 뒤 기준을 바꾸지 않도록 실험 전에 채택·폐기 조건을 정하는 것이 중요하다는 점을 배웠다.

## 5. 환각 원인 추적과 단일 변수 개선

복합 질문의 누락을 막기 위해 추가한 `효력의 성립·존속 여부·범위·기간` 확장 규칙이 오히려 영구 효력, 제출일 효력, 약관 관리 시스템 같은 원문 밖 내용을 만들 수 있음을 확인했다. 해당 규칙만 제거한 실험에서 환각이 사라지는 것을 확인하면서, 지침을 많이 추가하는 것이 항상 품질을 높이지 않으며 한 번에 하나의 변수만 바꾸어 원인과 효과를 분리해야 한다는 점을 배웠다.
