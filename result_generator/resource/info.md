# 카카오 약관 RAG 성능 개선 대회 안내

## 1. 대회 개요

이 대회는 카카오 약관에 관한 질문을 입력받아 정확한 답변과 근거 조항을 반환하는 RAG 결과기를 만드는 대회입니다.

결과기는 단순히 답변 문장을 생성하는 데 그치지 않고, 답변에 실제로 사용한 약관 문서와 조번호를 관련도 순으로 함께 반환해야 합니다. 정확도와 검색 품질이 중요하며, 응답속도도 측정하고 개선 과정의 기술적 판단을 설명할 수 있어야 합니다.

팀 번호는 **10번**입니다.

## 2. 진행 방식

- 1일차: 결과기 개발
- 2일차 13:30: 결과기 제출 마감
- 2일차: 운영진이 비공개 30문항으로 결과기를 실행하고 예선 채점
- 2일차 오후: 각 팀의 학생 평가기 개발
- 3일차: 본선 5팀 익명 교차 평가와 발표

공개 10문항은 연습과 개발용이며 예선 점수에는 포함되지 않습니다. 예선은 동일한 제출본을 운영진이 비공개 30문항으로 실행한 결과로 결정합니다.

공개 문항 ID나 문항 수에 맞춘 하드코딩은 금지합니다. 같은 결과기가 공개 10문항과 비공개 30문항을 모두 처리해야 합니다.

## 3. 예선과 본선

### 예선

- 운영진 평가기가 비공개 30문항의 결과를 같은 기준으로 채점합니다.
- 운영진 평가기의 총점만으로 상위 5팀을 선정합니다.
- 실패, null, 후보 누락, 후보 중복 또는 형식 오류가 있으면 평가 파일 전체가 순위 산정에서 제외될 수 있으므로 완전한 실행과 형식 준수가 최우선입니다.

### 본선

- 발표: 50점
- 결과기: 30점
- 교차 평가: 20점

## 5. 반드시 지켜야 할 결과기 계약

### 함수

```python
def answer_question(question: str):
    return {
        "answer": "질문에 대한 최종 답변",
        "retrieved": [
            ["카카오계정 약관", 10],
            ["카카오 통합서비스약관", 7],
        ],
    }
```

- 함수명과 입력 형식 `answer_question(question: str)`을 유지합니다.
- `answer`는 문자열이어야 합니다.
- `retrieved`는 실제 답변 생성에 사용한 근거만 관련도 순으로 1~4개 반환합니다.
- 각 근거는 `[문서명, 조번호]` 형식입니다.
- 검색 후보 전체를 `retrieved`에 넣지 않습니다.

### 허용 문서명

`retrieved`의 문서명은 아래 명칭을 그대로 사용합니다.

- `카카오계정 약관`
- `카카오 위치정보 이용약관`
- `카카오 통합서비스약관`
- `카카오 통합 약관`

원본 파일의 제목이 다르게 표시되더라도 반환값에서는 위 이름으로 매핑합니다. 특히 2022년 8월 25일 시행본은 원본 PDF 제목이 `카카오 통합서비스약관`이지만, 결과기의 문서명은 `카카오 통합 약관`으로 반환합니다.

### FastAPI

- 전역 `FastAPI app`을 제공합니다.
- `GET /health`를 제공합니다.
- `POST /answer`를 제공합니다.
- 공통 러너가 `/answer`에 `{"question": "..."}` 형식으로 요청합니다.

### 생성 모델

- 생성형 LLM은 Qwen2.5-Instruct 계열을 사용합니다.

## 10. 공개 문항에서 확인된 유형

공개 골드 문항에는 다음 유형이 포함되어 있습니다.

- `basic`: 일반적인 약관 사실 검색과 답변
- `exact`: 시간, 개월, 인원, 법조문 등 정확한 값이 중요한 질문
- `trap`: 질문에 포함된 잘못된 전제나 우선순위 함정을 약관 근거로 바로잡아야 하는 질문

## 11. 성능 측정 방식

### 예선 점수

비공개 30문항의 답변을 다음 세 항목으로 채점해 합산합니다.

- 근거 문서·조항 순위(MRR): 20점
  - `retrieved`에서 첫 정답 문서·조항이 1위면 1점, 2위면 0.5점, 3위면 약 0.33점, 4위면 0.25점, Top-4 밖이면 0점입니다.
  - 문항별 reciprocal rank를 비공개 30문항 전체에서 평균합니다.
- 핵심 내용 F1: 30점
  - 정답 핵심 내용과 답변 내용 토큰의 정밀도·재현율 균형을 평가합니다.
  - 핵심 내용 누락은 재현율을, 무관한 부연은 정밀도를 낮출 수 있습니다.
- 통합 LLM 평가: 50점
  - Gemini Flash와 Pro가 정확성 40%, 근거성 25%, 완결성 20%, 명료성 15%로 평가합니다.
  - 두 모델의 결과를 통합하여 비공개 30문항 전체에서 평균합니다.

최종 예선 점수는 반올림 전 수치로 `MRR 20 + 핵심 내용 F1 30 + 통합 LLM 평가 50`을 합산합니다. HTTP 성공률·처리량·응답시간은 기록하지만 점수에는 직접 반영하지 않습니다. 다만 필수 실행 형식 위반이나 답변 파일 생성 실패로 정상 채점할 수 없으면 별도의 제출·실격 규정이 적용됩니다.

### 실행 성능 기록

공통 러너는 답변 생성을 마친 뒤 같은 `/answer` 경로로 HTTP 성능을 측정합니다.

- 워밍업: 2요청
- 본 측정: 회당 12요청
- 반복: 3회
- 동시 요청: 2개

성능 측정값은 기록용이며 예선 점수에는 직접 반영되지 않는다고 안내되었습니다. 다만 평가와 발표에서는 품질과 속도의 균형에 대한 판단 근거로 사용합니다.

대표적으로 기록할 지표는 다음과 같습니다.

- 정확도 또는 운영진/학생 평가기 총점
- 정답 근거 조항 적중률 또는 Retrieval Recall@K
- 성공 문항 수
- 실패, null, 후보 누락과 중복 수
- 평균 응답시간
- P50, P95 응답시간
- 처리량(req/s)
- 전체 실행시간
- GPU 메모리 사용량(가능한 경우)
